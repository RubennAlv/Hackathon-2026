# 1. CONTEXTO DEL PRODUCTO

NEX24 es una plataforma de comercio inteligente que conecta proveedores, distribuidores, pequeños negocios, tiendas locales y consumidores.

Su objetivo es facilitar el descubrimiento de productos, el abastecimiento comercial y la conexión entre compradores y vendedores mediante tecnología.

NEX24 integra tres conceptos principales:

## 1.1. B2B — Business to Business

Conecta proveedores y distribuidores con pequeños negocios y establecimientos comerciales.

Los compradores empresariales pueden:
- Buscar proveedores.
- Consultar catálogos.
- Comparar precios.
- Consultar precios por mayoreo.
- Solicitar cotizaciones.
- Contactar directamente a proveedores.
- Comprar productos.
- Consultar disponibilidad.
- Gestionar pedidos.
- Encontrar proveedores en su zona.

Los proveedores pueden:
- Registrar su negocio.
- Publicar productos.
- Administrar catálogos.
- Gestionar inventarios.
- Establecer precios comerciales.
- Recibir solicitudes.
- Responder cotizaciones.
- Gestionar pedidos.
- Contactar compradores.

## 1.2. B2C — Business to Consumer

Permite que consumidores descubran y compren productos comercializados por vendedores locales.

La experiencia debe facilitar:
- Descubrimiento de productos.
- Búsqueda por categorías.
- Exploración de vendedores.
- Comparación de precios.
- Consulta de disponibilidad.
- Ubicación de productos.
- Contacto con vendedores.
- Compras y seguimiento de pedidos.

## 1.3. LENS IA — Reconocimiento inteligente de productos

Es uno de los principales diferenciadores tecnológicos de NEX24.

El usuario puede utilizar una cámara o cargar una fotografía para identificar un producto.

El sistema debe poder:
1. Capturar o recibir una imagen.
2. Analizar visualmente el producto.
3. Identificar posibles coincidencias.
4. Obtener información del producto cuando esté disponible.
5. Consultar el catálogo de NEX24.
6. Encontrar proveedores que comercializan productos coincidentes.
7. Mostrar precios, disponibilidad y ubicación.
8. Permitir contactar al proveedor o iniciar una compra.

IMPORTANTE:

El reconocimiento visual y la búsqueda comercial son responsabilidades diferentes.

La inteligencia artificial identifica posibles productos. El motor de búsqueda consulta los productos realmente registrados en NEX24.

No inventes proveedores, inventarios, precios ni coincidencias.

# 3. REGLAS INNEGOCIABLES

Estas reglas tienen prioridad sobre cualquier decisión de diseño o implementación.

## 3.1. Protección del sistema existente

ANTES DE MODIFICAR CUALQUIER ARCHIVO:

- Inspecciona la estructura completa del proyecto.
- Comprende cómo funciona el sistema.
- Identifica las funcionalidades existentes.
- Identifica los componentes reutilizables.
- Identifica las integraciones con backend.
- Identifica las rutas y sus dependencias.
- Identifica los modelos y contratos de datos.
- Identifica los mecanismos de autenticación y autorización.

Nunca reemplaces una funcionalidad existente por una interfaz decorativa.

Nunca elimines código solamente porque parece antiguo sin comprobar su utilización.

No reconstruyas funcionalidades que ya funcionan.

No modifiques contratos API sin una justificación técnica real.

No cambies modelos de base de datos, migraciones, autenticación, pagos ni reglas comerciales sin demostrar que es necesario.

## 3.2. Protección de Git

Antes de trabajar:

1. Ejecuta git status.
2. Identifica la rama actual.
3. Identifica los cambios sin confirmar.
4. Revisa los últimos commits.
5. Identifica archivos modificados por el usuario.

Nunca sobrescribas ni elimines cambios existentes del usuario.

No ejecutes:
- git reset --hard.
- git clean -fd.
- git checkout indiscriminado.
- comandos destructivos sobre el repositorio.

Si es posible, crea una rama de trabajo dedicada al rediseño, sin perder ni alterar cambios existentes.

No realices commits automáticos sin autorización.

## 3.3. No inventar funcionalidades

Primero identifica qué funcionalidades existen realmente.

Clasifica cada una como:

- Implementada y funcional.
- Implementada parcialmente.
- Implementada pero con errores.
- Solamente visual.
- No implementada.

No afirmes que una funcionalidad está terminada si solamente existe su interfaz.

Si detectas una funcionalidad nueva que aportaría valor, documéntala como propuesta y no la implementes sin evaluar sus dependencias y alcance.

## 3.4. Calidad de implementación

- Código modular.
- Componentes reutilizables.
- Tipado correcto.
- Separación de responsabilidades.
- Manejo de errores.
- Accesibilidad.
- Responsive design.
- Rendimiento.
- Seguridad.
- Mantenibilidad.

Evita:
- Componentes gigantes.
- Código duplicado.
- Lógica de negocio dentro de componentes visuales.
- Datos comerciales falsos.
- Botones sin funcionalidad.
- Formularios que no envían información.
- Enlaces rotos.
- Estados de interfaz inexistentes.
- Dependencias innecesarias.
- Refactorizaciones masivas sin justificación.
